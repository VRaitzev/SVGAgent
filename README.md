# ✨ Antigravity — AI-студия изометрических векторных композиций

Интерактивная веб-студия и мультимодальный AI-агент (VLM ReAct на базе LangGraph) для автоматической генерации, валидации и точечного редактирования изометрических SVG-иллюстраций по строгим правилам дизайн-системы.

---

## 🤖 Возможности и сильные стороны AI-агента (`AgentCore`)

Агент выступает в роли полноценного арт-директора и верстальщика, который умеет как **создавать композиции с нуля по абстрактной идее**, так и **выполнять точечные команды редактирования** над существующей сценой:

### 1. Три режима работы с запросами пользователя
* **Генерация сцены с нуля по смыслу и метафоре:** по запросам вроде *«собери сцену про учёбу и знания»* или *«рабочее место с фоновыми объектами»* агент сам подбирает смысловую пару (крупная база + мелкие аксессуары поверх неё + устойчивая вертикальная доминанта рядом + 1–2 монохромных фоновых силуэта с обрезкой краем холста).
* **Семантический и метафорический поиск (`search_components`):** агент ищет ассеты в `LanceDB` сразу в двух режимах (переключаются в UI):
  * **Весь каталог (`full_catalog`):** видит все доступные иллюстрации текущего размера (`L` или `S`) со всеми габаритами.
  * **Гибридный RAG (`rag` Top-K):** комбинирует мультимодальные/текстовые эмбеддинги с лексическим бустом по названию, описанию и концепт-ключу (`concept_key`).В режиме VLM агент также получает компактные превью (`256×256` JPEG) найденных кандидатов, чтобы видеть их форму до размещения на холсте.
* **Точечное и пакетное выполнение команд (`apply_scene_diff`):** агент понимает прямые инструкции по модификации текущей сцены без её пересоздания:
  * *«подвинь лампу левее и выше, чтобы она светила на книгу»* (`move_item_delta` / `update_item`);
  * *«переведи смартфон в фоновый монохромный слой»* (`toggle_item_role` + `move_item_to_layer`);
  * *«смени палитру на мятную и переключи детализацию на S»* (`apply_palette`, `set_detail_level`);
  * *«увеличь общий масштаб сцены до 0.8»* (`set_uniform_scale`);
  * *«поменяй порядок наложения ручки и папки»* (`reorder_item`);
  * *«покажи историю шагов и откати сцену к шагу #2»* (`list_history`, `revert_to_step`).

### 2. Цикл визуальной самопроверки (VLM Self-Critique Loop)
* **Рендеринг глазами агента (`inspect_and_validate_scene`):** после сборки или правки сцены бэкенд рендерит SVG-композицию в PNG через `resvg_py`, наносит на изображение **координатную линейку (`200, 400, 600 px`)** и передаёт кадр в VLM (`detail="high"`).
* **Контроль физики и композиции:** агент визуально проверяет рендер по чек-листу арт-директора:
  * стоячие предметы (лампа, ваза с тюльпанами) стоят на столе рядом с книгой/папкой, а не парят поверх раскрытых страниц;
  * мелкие плоские предметы (ручка, смартфон, монета, пазл) корректно лежат поверх крупных базовых объектов с правильным Z-order;
  * падающие чёрные тени не слипаются с границами соседних фигур (*защита от Tangent Trap*);
  * композиция сбалансирована и занимает `60–80%` ширины холста без эффекта «разреженного каталога иконок».

### 3. Инженерная оптимизация бюджета, памяти и отказоустойчивости
* **Пакетные транзакции (Batch Diffs):** вместо десятка мелких шагов по одному предмету агент обучен просчитывать координаты сразу всех объектов и объединять все сдвиги, добавления и смены ролей в **один комплексный вызов `apply_scene_diff`**.
* **Жёсткий контроль бюджета (`max_edit_steps`):** встроенный в инструменты счётчик правок и проверок предотвращает бесконечные циклы перфекционизма модели, укладывая генерацию сцены в **3–4 быстрых шага**.
* **Нулевое раздувание контекста (Zero Context Bloat):** base64-изображения рендеров и превью подкладываются динамически только в текущий шаг проверки (`_build_step_messages`) и не копятся в истории графа, экономя до 85% токенов и оперативной памяти.
* **Гарантированный Fallback-ответ:** даже при исчерпании лимита шагов или пустом ответе внешней LLM сервер никогда не падает с ошибкой — срабатывает автоматический retry с подсказкой и генерация финальной сводки по реальному состоянию холста.

## 🎯 Выполнение всех правил дизайн-системы и ТЗ

* **Смысловые слои и роли объектов (`Main` ↔ `Background`):**
  * **Главные объекты (`main`):** сохраняют конструктивные чёрные контуры, глубокие чёрные падающие тени и белые страницы, а цветные детали окрашиваются в акцентные цвета палитры (`accent_colors`).
  * **Фоновые объекты (`background`):** автоматически переводятся в **объёмный 4-ступенчатый монохром** (тёмный контур, мягкая тонированная тень, боковая грань и светлая верхняя грань) строго в пределах фоновых цветов схемы (`bg_colors`). Это сохраняет 3D-объём и читаемость деталей без использования акцентных цветов — один в один как на референсах Figma.
  * **Мгновенное переключение роли (`toggle_item_role`):** любой объект на холсте переключается между состояниями `Главный ↔ Фоновый` в один клик (или командой агенту) с автоматическим переносом в нужный слой и перекраской.
* **Единый изометрический масштаб (`uniform_scale`) и уровни детализации (`L` / `S`):**
  * Соблюдается правило истинной изометрии: пропорции отдельных объектов не искажаются относительно друг друга, масштабирование всей сцены выполняется синхронно.
  * Переключение композиции между крупными детализированными (`L`) и компактными упрощёнными (`S`) версиями иллюстраций по единому `concept_key` с сохранением центров координат.
* **Умная геометрическая и цветовая валидация (`Composition.validate`):**
  * Поддержка плотной журнальной вёрстки: разрешено осознанное наслоение мелких предметов поверх крупных плоских баз и композиционная обрезка краями холста (`Deliberate Crop`, при сохранении $\ge 30\%$ площади внутри кадра).
  * Строгая блокировка цветовых нарушений (акцентные цвета главных объектов запрещены в фоновом слое и на фоне холста) и полных коллизий одноразмерных объектов.
* **3+ преднастроенные цветовые схемы + пользовательские палитры:**
  * *Лавандовая (`lavender_mist`)*, *Персиковая (`peach_sunset`)*, *Мятная (`mint_breeze`)* и возможность регистрации собственных палитр через API/UI.

## 🏗 Архитектура проекта

```text
├── Dockerfile                 # Multi-stage сборка (React build + Python runtime с оптимизацией под 512MB RAM)
├── src/
│   ├── backend/
│   │   ├── server.py          # FastAPI сервер (REST API, раздача статики React, экспорт SVG/PNG)
│   │   ├── AgentCore.py       # Мультимодальный ReAct-агент (LangGraph, JPEG-сжатие, линейка 800x800, бюджет)
│   │   ├── agent_tools.py     # Реестр инструментов агента (поиск, сборка сцены, пакетный diff, инспекция, история)
│   │   ├── scene_session.py   # Транзакционная сессия (Undo/Redo/Revert, L↔S, Main↔Background, валидация)
│   │   ├── composition.py     # Геометрия холста 800×800, слои, bbox с учётом поворота и правила ТЗ
│   │   ├── palette.py         # Палитры и алгоритм распределения цветов по яркости (luminance mapping)
│   │   ├── svg_image.py       # Парсер SVG-метаданных, нормализация CSS/HEX-цветов и viewBox
│   │   ├── svg_store.py       # Хранилище компонентов на базе LanceDB (гибридный векторный + текстовый поиск)
│   │   ├── renderer.py        # Сборка итогового SVG-дерева, изоляция XML ID и рендеринг в PNG (resvg_py)
│   │   └── data/              # Предзаполненная база LanceDB (28 изометрических SVG-ассетов L/S, Main/Bg)
│   └── frontend/
│       ├── src/App.jsx        # Интерактивный редактор (drag/rotate, слои, палитры, чат с агентом, таймлайн)
│       └── src/api.js         # Клиент взаимодействия с FastAPI
